Locator memory

{% if build.locator_memory %}

Each interaction step in the trace above is badged healed or freshly derived. Memory engages where a locator has stopped resolving — that is the case it exists for — so a run where nothing broke is a run of freshly derived locators, which is the expected reading rather than a missing feature. Where memory was consulted and contributed nothing, the step says which kind of nothing: empty, past its confirmation window, or quarantined after three consecutive failures.

The boundaries are the design. A locator enters memory only from a run that ended succeeded_verified, never merely because a click worked. What is remembered is an element's identity and never a value, so nothing here can become an answer. And a remembered locator is re-resolved on the live page and re-verified like any other: memory saves search effort, never proof.

Counters are on /healthz, and on a healthy deployment they read stored: some, used: zero — because using a remembered locator requires one to have stopped resolving first, and none has here. That zero is a measurement rather than a silence: the stored rows are proof the write path runs, so the counter is one that can move and has had nothing to count. The endpoint says which of the two it is rather than leaving a reader to assume.
